# Proof & State Context

Use this reference only for work involving Proof & State, OpsTruth, DoneState, or AI Work Accountability. It records durable architecture from the originating work session, not current release status.

## Durable architecture

```text
Proof & State
Infrastructure for AI Work Accountability

OpsTruth
Independent, read-only verification of AI-assisted development claims

DoneState
Governed execution, continuity, and accountability for unresolved work
```

The lifecycle concept is:

```text
Agent works
OpsTruth verifies evidence
DoneState maintains accountability
Unresolved work returns to authorised execution
OpsTruth verifies the new completion claim
```

This is a strategic relationship, not proof of a working protocol. Reverify the handoff contract and one fresh end-to-end run before claiming interoperability.

## Trust boundary

OpsTruth remains the independent verifier. It should not gain mutation, remediation, deployment, or general write authority merely to close a product loop. Private-repository read access is distinct from write authority. DoneState or another execution plane may act only with explicit authority and should produce evidence for independent verification.

## Positioning

Primary problem language:

"AI Work Accountability" is the umbrella category. Qualify it as "for software agents" when ambiguity with employee-monitoring products could mislead the audience. Recheck category and competitor use before a major campaign.
